# Genie Code Dashboard Demo Script

A four-stage demo showing how Genie Code output for Lakeview dashboard authoring improves at each step — from ungoverned dashboards to Nokia-standard exec dashboards with centralized skills via MCP.

### Configure these values for your environment

| Variable | Description | Example |
|----------|-------------|---------|
| `{catalog}` | Your Unity Catalog name | `nokia_catalog` |
| `{schema}` | Your schema name | `workshop` |

> Replace `{catalog}` and `{schema}` throughout this script with your actual values.

---

## Data Source Options

Choose the option that matches your workshop setup:

**Option A — Full capstone (Sessions 1 + 2 completed)**

Uses gold tables from Session 1 and churn predictions from Session 2:
- `{catalog}.{schema}.gold_account_summary` — customer/account gold table
- `{catalog}.{schema}.churn_predictions` — ML churn scores from Session 2

**Option B — Standalone (no prior sessions needed)**

Uses only the financial gold table generated by the sample data pipeline:
- `{catalog}.{schema}.gold_account_summary` — contains account balance, region, income tier, credit tier, product type
- Use `credit_tier = 'Poor'` or `account_balance < threshold` as a proxy for at-risk customers instead of a churn score

All prompts below support both options — substitute accordingly.

---

## Prerequisites

1. A Lakeview dashboard has been created (or create a blank one in the Databricks UI)
2. Genie Code is open in **Agent mode** inside the dashboard
3. Gold tables are available in `{catalog}.{schema}`

---

## Stage 1: Baseline (No Skills, No Instructions, No MCP)

**Goal:** Show that Genie Code builds a functional dashboard but without Nokia standards — generic names, missing KPIs, no standard filters or layout.

### Setup

- No skills uploaded to the workspace
- No `.assistant_dashboard_instructions.md` file
- No MCP connections enabled in Genie Code

### Prompts

Open Genie Code in Agent mode inside a Lakeview dashboard:

**Prompt 1a:**

> Build me an executive dashboard for churn analysis using `{catalog}.{schema}.gold_account_summary`

**Prompt 1b:**

> Add KPI tiles for total customers and churn rate

**Prompt 1c:**

> Add a chart showing churn by region and a filter for time period

### What to observe

Point out what's **missing**:

- [ ] Dashboard named `New Dashboard` or `Untitled` — no Nokia naming
- [ ] Datasets named `Dataset 1`, `Dataset 2` — no `ds_` prefix or descriptions
- [ ] KPIs missing — no standard 4-tile row, no period-over-period delta
- [ ] No `NULLIF` in SQL denominators (divide-by-zero risk)
- [ ] Filter bar missing or incomplete — no `filter_region`, `filter_segment`
- [ ] No section headers between chart groups
- [ ] Missing standard slices — no income tier breakdown, no product type breakdown
- [ ] No at-risk detail table
- [ ] Inconsistent chart colors

> **Talking point:** "Genie Code builds a working dashboard, but every team produces something different. An exec gets 5 dashboards that look and feel nothing alike — no standard KPIs, no consistent slices."

### Cleanup before Stage 2

Delete the datasets and widgets created in Stage 1 or start with a fresh blank dashboard.

## Stage 2: Add Skills

**Goal:** Show that uploading dashboard skills immediately produces Nokia-standard exec dashboards.

### Setup

Upload the three skill files from `skills/dashboard/` to your workspace:

```
skills/dashboard/              (repo)        →   Workspace/.assistant/skills/   (workspace)
  dashboard-naming.md                              dashboard-naming.md
  dashboard-kpis.md                                dashboard-kpis.md
  dashboard-layout.md                              dashboard-layout.md
```

Or upload to user level at `/Users/{username}/.assistant/skills/` for a personal demo.

> **Note:** The file name (e.g. `dashboard-naming.md`) becomes the `@tag` name — `@dashboard-naming` tells Genie Code to load and apply that skill.

### Prompts

Start a **new** Genie Code session:

**Prompt 2a:**

> Build me an executive churn dashboard using `{catalog}.{schema}.gold_account_summary` — apply @dashboard-naming and @dashboard-kpis as standards

**Prompt 2b:**

> Add the standard layout with filters, section headers, and the at-risk customer table — apply @dashboard-layout

### What to observe

Compare side-by-side with Stage 1:

- [x] Dashboard named `Nokia_Churn_Analysis_Exec`
- [x] All datasets prefixed `ds_` with SQL description comments
- [x] All widgets named `kpi_`, `bar_`, `trend_`, `tbl_` etc.
- [x] All 4 standard Nokia KPIs in top row with period-over-period delta
- [x] SQL uses `NULLIF` in denominators and `ROUND()` for rates
- [x] Filter bar with `filter_time_period`, `filter_region`, `filter_segment`
- [x] Section headers: Churn Trends, Customer Segments, At-Risk Detail
- [x] All 4 standard slices: region, product type, income tier, time trend
- [x] At-risk customer table as last section
- [x] Consistent Nokia color palette

> **Talking point:** "Same prompt, Nokia-standard exec dashboard. Every team, every dashboard, same structure — the exec always knows where to look."

### Cleanup before Stage 3

Stage 3 uses the same prompts — clear the dashboard or start fresh.

## Stage 3: Add Instructions

**Goal:** Show that dashboard instructions make skills automatic — no `@mention` needed.

### Setup

Keep the skills from Stage 2 in place. Add a user-level dashboard instructions file:

1. Copy `local_deployment/instructions_to_use/user_dashboard_instructions_skills.md`
2. Upload as `/Users/{username}/.assistant_dashboard_instructions.md` in your workspace

### Prompts

Start a **new** Genie Code session:

**Prompt 3a:**

> Build me an executive churn dashboard using `{catalog}.{schema}.gold_account_summary`

**Prompt 3b:**

> Add the standard layout, filters, and at-risk customer table

### What to observe

- [x] **No `@skill` mentions needed** — instructions apply dashboard standards automatically
- [x] All the same Nokia standards as Stage 2
- [x] Instructions route dashboard authoring work to the right skills automatically

> **Talking point:** "Every dashboard author in Nokia gets exec-standard output by default. No training required on which skills to invoke."

### Cleanup before Stage 4

Delete or reset the dashboard for a clean Stage 4.

## Stage 4: MCP (Centralized Standards from GitHub)

**Goal:** Show Nokia dashboard standards served centrally from GitHub — no local skill files needed.

### Setup

1. **Delete the local skills** from the workspace:
   - Remove `Workspace/.assistant/skills/dashboard-naming.md`
   - Remove `Workspace/.assistant/skills/dashboard-kpis.md`
   - Remove `Workspace/.assistant/skills/dashboard-layout.md`

2. **Add the MCP connection** to Genie Code:
   - Open Genie Code settings → Add MCP server → select `genie-code-skills-mcp`
   - Enable: `get_file_contents`, `search_code`

3. **Switch instructions to MCP version**:
   - Replace with `local_deployment/instructions_to_use/user_dashboard_instructions_mcp.md`
   - Upload as `/Users/{username}/.assistant_dashboard_instructions.md`

### Prompts

Start a **new** Genie Code session:

**Prompt 4a:**

> Build me an executive churn dashboard using `{catalog}.{schema}.gold_account_summary`

**Prompt 4b:**

> Add the standard layout, filters, and at-risk customer table

**Prompt 4c (bonus — Option A only):**

> Extend the dashboard to include churn scores from `{catalog}.{schema}.churn_predictions` — add a KPI for revenue at risk using the ML model scores

### What to observe

- [x] Genie Code **fetches skills from GitHub** via MCP (`get_file_contents` calls visible)
- [x] Same Nokia standards — identical to Stages 2 and 3
- [x] **No local skill files** needed in the workspace
- [x] Dashboard standards version-controlled in GitHub — update once, all workspaces benefit

> **Talking point:** "The Nokia BI team owns the dashboard standard in one GitHub repo. Every workspace, every author, every dashboard — same exec view, automatically."

## Prompt Reference Bank

A focused set of prompts for hands-on use during the workshop.

> Replace `{catalog}` and `{schema}` with your actual values. For Option A, also replace `{churn_predictions_table}` with your ML output table.

---

### 1. Build the Foundation

**Prompt 1 — Create the exec dashboard**

> Create a Nokia executive churn dashboard using `{catalog}.{schema}.gold_account_summary`.
> - Name it `Nokia_Churn_Analysis_Exec`.
> - Add the 4 standard Nokia KPI tiles: Total Active Customers, Churn Rate %, Revenue at Risk, and High-Risk Customer Count.
> - Include period-over-period delta on each KPI.
> - Use safe SQL (NULLIF in denominators, ROUND for rates).

**Prompt 2 — Add filters and standard slices**

> Add the standard Nokia filter bar and exec slices to the dashboard:
> - Filters: Time Period, Region, Customer Segment (connected to all datasets).
> - Charts: monthly churn trend, churn by region, churn by product type, churn by income tier.
> - Use Nokia naming conventions for all widgets and datasets.

---

### 2. Add Detail and At-Risk View

**Prompt 3 — At-risk customer table**

> Add an At-Risk Detail section at the bottom of the dashboard:
> - Table showing top 50 customers ranked by revenue at risk (account_balance × churn_score).
> - Columns: customer_id, region, income_tier, account_balance, churn_score_pct, revenue_at_risk.
> - Add a section header above the table.

**Prompt 4 (Option A — with ML scores) — Integrate churn predictions**

> Extend the Revenue at Risk KPI and at-risk table to use churn scores from `{catalog}.{schema}.churn_predictions`.
> - Join on `customer_id`.
> - Use `churn_score` from the predictions table instead of any proxy.
> - Update the KPI SQL and the at-risk table dataset to reflect the ML-derived score.

---

### 3. Refine and Polish

**Prompt 5 — Layout and color polish**

> Review the dashboard layout and apply Nokia standards:
> - Ensure section headers are present between Churn Trends, Customer Segments, and At-Risk Detail sections.
> - Apply Nokia color conventions: red for increasing churn, green for decreasing, blue for neutral.
> - Ensure KPI tiles are in a 4-column row, charts are in 2-column rows, and the table is full width.
